# ADR 0008:补丁协议 —— 块锚定局部编辑,不做全文件重写

日期:2026-10-08 | 状态:已采纳 | 素材:`app/gitops/blockpatch.py` 实现与 `tests/test_blockpatch.py`
(本 ADR 是"事后补记":决定早已随实现落地,但四篇核心 ADR 里没有一篇写它,而它是 ACI 层最关键的一条)

## 背景

Agent 改代码只有三种可交付形态,选哪一种决定了失败模式的分布:
全文件重写要模型逐字复述整个文件(截断、漏行、把行尾与"末行无换行符"的状态改掉都算改动);
裸 unified diff 要模型自己写 `@@ -a,b +c,d @@` 的行号(而它只能靠 `read_file` 的窗口猜);
块锚定替换只给"上下文 + 增删行",行号由系统算。
平台侧还有既定的防线链(静态门禁 → 落点校验 → `git apply --check` → 快照 → apply → ast 预检),
新协议不能要求它们改判据。

## 候选

1. **全文件重写**(`write_file` 整文件覆盖);
2. **裸 unified diff**(模型直写 diff 文本与行号);
3. **块锚定替换**(采纳):模型只写 `*** Begin/End Patch` + Update/Add/Delete 段,
   段内是空格上下文行、`-` 删除、`+` 新增、`@@` 分块、`\` 转义。

## 结论

采用块协议,并让它**编译到 unified diff 而不是替代它**:unified diff 仍是系统内唯一事实源,
`compile_block_patch` 把块变成带真实行号的 diff 之后,防线链一个字节都不改。

三条设计要点:

- **行号由编译器算,不由模型写**。`_locate` 在磁盘前像里找该上下文块的命中位:0 处拒
  `anchor_not_found`,多处拒 `ambiguous_anchor`(并要求模型补更多上下文使其唯一),
  早于游标拒 `chunks_out_of_order`。"模型写错行号"这一整类失败模式在协议层消失。
- **行尾按字节保真**。切行用 `split_keepends`(只按 `\n`),禁用 `str.splitlines()`
  ——它还会在 `\x0b \x0c \x1c-\x1e \x85 \u2028` 处切行,会把前像切碎;也禁用
  `Path.read_text`(universal-newlines 会把 CRLF 静默变 LF)。`no newline at end of file`
  独立成行,否则 `git apply` 判 corrupt patch。
- **段头路径先 fail-fast 判一次**,门禁与落点校验照旧复查(双防线,不因协议层提前拒而放宽任何一条)。

## 后果(含反方)

- `+`:模型的输出量与文件长度解耦(改 3 行就写 3 行),行号与上下文一致性问题被编译器接管;
- `−`:**上下文重复的真实金补丁无法机械 round-trip** —— 同一份前后文在文件里出现多处时,
  转换器给不出唯一落点,而模型可以靠补上下文自纠。已按此口径把这类题排除出题集,不假装能覆盖;
- `−`:rename/copy 与二进制 diff 不迁移(`_record_action` 明确拒),这类改动要用 Add+Delete 两段表达;
- `−`:`ambiguous_anchor` 是额外一轮消耗 —— 模型第一次往往写不够长的上下文;
- 协议层新增 4 个拒绝细类(都归到既有 `context`/`format`/`paths` 词表),门禁判据未动;
- **未证明**:块协议相对裸 unified diff 对真实模型修复率的提升幅度没有对照数据
  (FakeLLM 照不出提示词与协议差别),这条只能由真实模型批主张(待授权)。
