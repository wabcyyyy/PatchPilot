# ADR 0013:连续会话与任务记忆 —— 阶段之间带过去的是平台观测,不是模型自述

日期:2026-10-11 | 状态:已采纳 | 素材:SPEC §7 G06、§4 契约 5/6、§1 缺陷 2、评审 `agent-readiness-review-2026-10-10.md` R2、`runs/swe-hard-graph2`/`runs/swe-hard-graph3`

## 背景

`LOCALIZE → PLAN → PROPOSE` 三段各自跑一次 `run_plain_loop`,阶段之间只交接两样东西:
`findings`(定位阶段 finish 时**模型自己写的那段话**)与 `plan`(计划阶段的文本)。
平台从来没有登记"模型到底读过哪些行、哪次检索返回了什么、哪个假设被什么打脸"。

这条缺陷有付费现场,而且现场里能看出它值多少钱:同一题(sphinx-7590)两次独立运行
(`runs/swe-hard-graph2`、`runs/swe-hard-graph3`),定位阶段读过目标文件之后,
补丁阶段仍然 **13 次 search_code / 10 次 read_file、`apply_patch` 0 次**,最后撞任务级总额
BUDGET_EXCEEDED。当时的归因是"暂定 findings 太薄"(于是 M11 把已查线索拼进 findings,
63→397 字符),**复验后补丁阶段的重复调查一次没少** —— 被数据推翻的预测登记在
PROGRESS 第 9 项:在提示里给线索并不约束模型行为。真正缺的不是"更长的自述",
而是"平台可核对的观测 + 它对新阶段可见"。

SPEC §1 缺陷 2 说的正是这一件:阶段间只传薄摘要,代码与失败证据丢失。

## 候选

1. **把上一阶段的完整 messages 灌进下一阶段**:信息最全,但请求体积随轮数线性膨胀
   (实测那种 16-19 轮只读调查就是几十屏),而且"看见过"不等于"知道哪条还是现状"——
   补丁改过文件之后,旧对话里的行范围反而变成误导;
2. **让模型自己写跨阶段摘要**:成本小,但摘要不可核对(它说读过 X 平台无从验证),
   并且模型会把推测写成事实——SPEC 契约 5 明令"事实与模型假设分开";
3. **平台从真实工具回执自动登记观测 + 模型只能提交带引用的假设 + 装配器按版本装配**(采纳)。

## 结论

- **观测由平台写**:`registry.execute()` 每条真实回执过一道 `describe_receipt`,
  折成一行可核对的事实(工具名 + 对象 + 计数 + 行范围)进 `TaskMemory`,模型不参与、
  也不需要它配合。失败回执同样登记 —— 走死的口子比成功更能阻止下一阶段重复同一次调查。
- **模型只有一个通道**:`update_memory(hypotheses, excluded)`,状态词表只有
  `hypothesis|supported|refuted`;`supported/refuted` 必须引用记忆里真实存在的观测号,
  写 `verified/confirmed/resolved` **点名拒绝**而不是静默降级(替模型改写它的说法是不诚实的)。
  渲染时三区分开:`平台观测` / `平台判定` / `模型假设(未经平台验证)`,模型的话不会伪装成事实。
- **失效要看得见**:每条观测带登记时的 `workspace_revision`;`apply_patch` / `reset_workspace`
  成功、以及 rollback 的 `reset_workspace`(平台动作,不走工具层)都会推进代数并把更早的
  观测标 `stale`。G05 的 `evidence_id` 一起带过去,所以记忆块里直接写着
  `read_evidence("…")` 怎么取原文 —— 两个卡在这一条上接上了。
- **装配面 == 记忆面**:`ContextAssembler` 按 `(阶段, 轮次)` 幂等装配,同一阶段第二次装配
  复用第一次的成品并标 `reused`;骨架在前、记忆块随后、各只出现一次。这挡住的是
  "每进一个阶段就再抄一份说明"的叠加(纯成本,不是信息)。
- **配对规则只有一处实现**:`SessionState.repair_orphans()` 在**发送之前**检查即将发出去的
  消息,给"assistant 声明了 tool_call 但没有回执"补一条显式占位(内容就是"没有记录到结果",
  不伪造成功),并落 `message_pairing_repaired` 事件。此前这条不变量散在四个回填分支里靠自觉。
- **恢复必须认得回哪一条会话**:turn 边界快照带着 `session_id / session_hash /
  memory_version / memory_hash`,记忆本体在**同一个边界**落 `memory_state.json`;
  `binding_mismatch()` 只在两侧都有绑定且不一致时才拒绝恢复 → 待审,不默默冷启动一次
  用错版证据的运行(SPEC:不从薄摘要默默重新启动)。

## 代价与反方

- 记忆块与仓库骨架、(G08 的)项目说明抢同一份 system 预算。`task_memory_max_chars=3000`
  是拍的起点值,G07 抬窗口时必须三者一起标定,否则先被挤掉的总是证据。
- **同一阶段内新增的观测不会立刻出现在本阶段的 system 里**(装配幂等的直接后果)。
  跨阶段、跨轮次会重装配。选择幂等而不是"每轮重渲染",是因为每轮重渲染等于每轮改写
  stable prefix,而前缀改写会打掉提示缓存 —— 这是工程取舍,不是"证据会自动同步"的承诺。
- `update_memory` **不进 PLAN 阶段**:PLAN 的可见面仍然只有 `finish`,否则 G01 立的
  "一段合规纯文本就是阶段结束"的单次文本契约会被重新打开(模型多了一个可调用手段,
  就要多一次协议修正额度)。计划文本由平台代登记进记忆(`record_plan`),不靠模型自觉。
- 未绑定的历史快照**不算 mismatch**,继续走既有冷启动语义。把"没绑定"也判成待审,
  等于让升级前留下的每一份快照一律需人工复核 —— 那是伪造迁移成功,不是严格。
- 分支候选的 ctx 用自己的 `report_dir` ⇒ 候选之间、候选与主流程之间**不共享**记忆与证据索引
  (引用别人的 id 读成 not found)。G13 要给子任务传证据包时,得先把"合法共享域"定下来。
- 观测是**索引不是正文**:记忆块里只有"读过哪个文件哪些行、命中几条、判定是什么"。
  要内容请用 `read_evidence` / 重新 `read_file`。这条限制让记忆块能进 system,
  但也意味着模型可能因为"只看到索引"而再读一遍 —— 省不省请求,离线不知道(G17)。
- 离线全绿只证明接线与形状:**不证明修复率、不证明重复调查变少**。T10 的断言对象是
  "PLAN 那一次实际请求里带着 `[E1] LOCALIZE r0 read_file … 行 1-…` 与取回引用",
  它证明传递,不证明有用。
