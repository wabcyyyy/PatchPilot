# ADR 0007:计划工件 —— PLAN 成为图上的一个节点,而不是提示里的一句话

日期:2026-10-07 | 状态:已采纳 | 素材:PROGRESS.md D.8/M4/M5、runs/swe-hard-graph2/3

## 背景

状态机原本是 `LOCALIZE → PROPOSE → APPLY → VERIFY`。"计划如何修复"只是
`LOCALIZE_PROMPT` 要求模型塞进 `finish.summary` 的一段自由文本,既不在 state 里,
也没有独立的产生步骤。实测后果(`runs/swe-hard-graph2/3`,同一题两次独立跑法同形):
补丁阶段拿着 63-397 字符的定位摘要,13 次 search / 10 次 read、`apply_patch` **0 次**
——它重新调查,而不是动手改。失败重试侧同样缺工件:verify 失败后工作区被硬复位,
下一轮 PROPOSE 是新会话,只拿到失败用例的签名与堆栈,"上一轮到底改了什么"随工作区一起消失,
于是 `repeat_streak`(同一组失败连续多轮完全一致)成为常态信号。

## 候选

1. **提示层加一句"先想清楚再改"**:零成本,但无工件、不可审计、下一轮仍然冷启动;
2. **PROPOSE 内设"必须先写计划"的工具闸门**:不额外发请求,但把计划与执行混在同一段会话里,
   失败轮的"上一版计划"仍然没有独立载体,而且会改变补丁阶段的工具白名单(禁区语义);
3. **独立 PLAN 节点 + state 工件**(采纳)。

## 结论

- `TaskState.plan: str`(纯字符串,可 checkpoint)由新节点 `plan` 产生:一次只允许 `finish`
  工具调用的循环,产出"目标文件/符号 + 失效机制 + 最小改动意图 + 预期如何被验证证实"。
  刻意不给检索/写入工具——**"先计划"不能变成"再调查一轮"**。
- 失败轮回到 PLAN 而不是直接回 PROPOSE(`apply` 的重试边与 `rollback` 的重试边都改指 PLAN),
  于是同一份工件被**修订**;状态字符串一字未改(`PROPOSE_PATCH` 等照旧),
  终态与门禁语义零漂移。`recursion_limit` 由 `4N+8` 抬到 `5N+8`(每轮多一个 superstep)。
- 计划的额度是"任务剩余额度 × `plan_budget_share`(默认 0.15)",走既有 `_token_budget_for`
  与 `ensure_budget` 通道,不新增额度;计划段份额耗尽 → 带模型最后一轮实质文本降级继续
  并落 `plan_degraded` 事件(与 LOCALIZE 同构);任务级总额耗尽仍是硬终点(N-5 未动)。
- 计划与 PROPOSE 共享同一份持久记忆(仓库骨架)与反思文本(M4 的 discarded-patch 形状摘要),
  三者共同回答"该改哪儿、上一版为什么不算"。
- **测试面兼容**是本卡最大的工程风险:`FakeLLM` 按固定脚本逐步回放,多一次调用就会让
  `tests/test_graph.py` 的 25 例全部错位。做法是 PLAN 提示带 `[[plan_stage]]` 标记,
  FakeLLM 认出标记后**不移动游标**直接返回"计划文本 + finish";用例断言
  计划开/关两次的 `consumed` 相等且等于脚本长度。真实模型侧确实多发一次请求。

## 后果(含反方)

- +:计划成为可审计、可修订、可 checkpoint 的对象;跨轮回同一工件修订而不是冷启动重猜;
  fake 回放与两臂对照的既有口径不被静默改变;
- −:多一次 LLM 调用(每轮),在真实批次里是实打实的成本与延迟;
- −(反方,必须一起读):**FakeLLM 无视消息内容**(ADR-0003 自认),所以零成本回放
  只能证明"接线不破既有行为",**不能**证明计划提高了修复率。这条主张目前未证明,
  要证明必须真实模型批(人工授权后按 `docs/swe-ablation-evidence-2026-10-07.md` 的
  预登记判据跑);
- −:消融臂(`single_shot`)不加计划段,因此将来任何两臂对照都必须先把 `plan_stage`
  登记进消融变量,否则对照会多出一个未登记的差异(本仓库已为此作废过一次付费实验)。
