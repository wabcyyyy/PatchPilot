# ADR 0007:计划工件 —— PLAN 成为图上的一个节点,而不是提示里的一句话

日期:2026-10-07 | 状态:已采纳 | 素材:PROGRESS.md D.8/M4/M5、runs/swe-hard-graph2/3

## 背景

状态机原本是 `LOCALIZE → PROPOSE → APPLY → VERIFY`。"计划如何修复"只是
`LOCALIZE_PROMPT` 要求模型塞进 `finish.summary` 的一段自由文本,既不在 state 里,
也没有独立的产生步骤。实测后果(`runs/swe-hard-graph2/3`,同一题两次独立跑法同形):
补丁阶段拿着 63-397 字符的定位摘要,13 次 search / 10 次 read、`apply_patch` **0 次**
——它重新调查,而不是动手改。失败重试侧同样缺工件:verify 失败后工作区被硬复位,
下一轮 PROPOSE 是新会话,只拿到失败用例的签名与堆栈,"上一轮到底改了什么"随工作区一起消失,
于是 `repeat_streak`(同一组失败连续多轮完全一致)成为常态信号。

## 候选

1. **提示层加一句"先想清楚再改"**:零成本,但无工件、不可审计、下一轮仍然冷启动;
2. **PROPOSE 内设"必须先写计划"的工具闸门**:不额外发请求,但把计划与执行混在同一段会话里,
   失败轮的"上一版计划"仍然没有独立载体,而且会改变补丁阶段的工具白名单(禁区语义);
3. **独立 PLAN 节点 + state 工件**(采纳)。

## 结论

- `TaskState.plan: str`(纯字符串,可 checkpoint)由新节点 `plan` 产生:"目标文件/符号 + 失效机制 +
  最小改动意图 + 预期如何被验证证实"。能力集合只有 `finish`,不给任何检索/写入工具——
  **先计划不能变成再调查一轮**。G01 之后这条从"执行时挡下"升为"模型看不见"(见下"完成协议修订")。
- 失败轮回到 PLAN 而不是直接回 PROPOSE(`apply` 的重试边与 `rollback` 的重试边都改指 PLAN),
  于是同一份工件被**修订**;状态字符串一字未改(`PROPOSE_PATCH` 等照旧),
  终态与门禁语义零漂移。`recursion_limit` 由 `4N+8` 抬到 `5N+8`(每轮多一个 superstep)。
- 计划的额度是"任务剩余额度 × `plan_budget_share`(默认 0.15)",走既有 `_token_budget_for`
  与 `ensure_budget` 通道,不新增额度;计划段份额耗尽 → 带模型最后一轮实质文本降级继续
  并落 `plan_degraded` 事件(与 LOCALIZE 同构);任务级总额耗尽仍是硬终点(N-5 未动)。
- 计划与 PROPOSE 共享同一份持久记忆(仓库骨架)与反思文本(M4 的 discarded-patch 形状摘要),
  三者共同回答"该改哪儿、上一版为什么不算"。
- **测试面兼容**是本卡最大的工程风险:`FakeLLM` 按固定脚本逐步回放,多一次调用就会让
  `tests/test_graph.py` 的 25 例全部错位。做法是 PLAN 提示带 `[[plan_stage]]` 标记,
  FakeLLM 认出标记后**不移动游标**直接返回"计划文本 + finish";用例断言
  计划开/关两次的 `consumed` 相等且等于脚本长度。真实模型侧确实多发一次请求。

## 完成协议修订(G01,2026-10-10)

M5 落地时留了一条自相矛盾:提示要求"不要调用任何工具",而循环只认 `finish` 才正常返回。
遵守提示的真实模型因此**必须**把阶段份额烧到 `max_turns`/`phase_share` 才"退出"。读数:
`docs/work-notes/agent-readiness-review-2026-10-10.md` 的 R1 —— 真实 Q0 里 PLAN 共 132 次请求、
624,599 tokens(全批 8.78%)、20/21 题以 `plan_degraded(reason=phase_share)` 收场,只有 1 题正常
finish;本地复现 = 连续三条合规纯文本 → `{calls: 3, error: "agent loop exceeded max_turns=3"}`。
`FakeLLM` 对 `PLAN_MARKER` 的特判(自动补 finish 且免消耗脚本步)把这条在离线回放里掩盖掉了。

本次修订四件事:

1. **单次文本完成契约**(`run_plain_loop(complete_on_text=True)`,只给计划段开):一段
   非空、未被 `max_tokens` 截断、且不要求任何工具的回复**就是本阶段正常结束**
   (`LoopOutcome.completion="text"`)。默认 `False` = 既有循环形状逐字不变。
2. **有界协议修正**:空回复 / 截断 / 越权工具调用最多换一次确认(`MAX_PROTOCOL_REPAIRS = 1`),
   越权调用**不进执行**、只留一条 blocked 取证事件(零副作用);仍不合协议就以
   `completion="protocol_invalid"` + `protocol_reason` 结构化结束,节点落 `plan_invalid` 事件后
   照常进 PROPOSE。**终点集合一字未动**(仍只有 NEEDS_REVIEW / BUDGET_EXCEEDED),
   也没有新增放行模式;计划完成永远不等于修复成功。
3. **可见面 == 执行面**:`tool_schemas(allowed_tools)` 只装配本阶段能力,与执行前的白名单复核
   同源。此前每阶段都把全量 schema 发出去,模型看得到 `apply_patch`/`run_tests`/`reset_workspace`
   却每次都被挡 —— 一次越权就是一次真实请求。白名单里出现未注册的名字现在当场报错。
4. **FakeLLM 两条通道**:`plan_mode="legacy"`(默认)保留"文本 + finish 且免脚本步"的历史回放
   形状;`plan_mode="strict"` 下计划请求按普通脚本步回放,单次文本契约由它来证 ——
   契约成立与否不能由 marker 自动补 finish 来宣布。

- 反方与未证明(必须一起读):
  - 修正额度取 1 是**按失败形状定的**,不是标定出来的最优值:Q0 里"继续问"就是继续烧份额;
    1 是否偏保守要真实两臂才能说,而这类差异落在 Q0 实测的 token 噪声(±26%)里分辨不出来。
  - 真实模型会不会稳定给出"非空且未截断的纯文本计划"没有在线证据;本批只证协议侧不再依赖
    finish,以及不合规路径有界。**G17 之前不得写成效果主张**。
  - `plan_invalid` 之后带的是**最近**一段实质文本进 PROPOSE,那段文本可能就是"我先看代码"这类
    无计划价值的话。平台的承诺只是"不再把份额烧光",不是"降级产物可用"。
  - 续跑时修正计数从 0 重计(A 级快照只存 messages 与三个用量,没有协议状态)。最坏情形是同一段
    在多次恢复里各问一次修正。把它持久化要改快照形状,属 G05/G06 的范围,这里只登记不偷做。

## 后果(含反方)

- +:计划成为可审计、可修订、可 checkpoint 的对象;跨轮回同一工件修订而不是冷启动重猜;
  fake 回放与两臂对照的既有口径不被静默改变;
- −:多一次 LLM 调用(每轮),在真实批次里是实打实的成本与延迟;
- −(反方,必须一起读):**FakeLLM 无视消息内容**(ADR-0003 自认),所以零成本回放
  只能证明"接线不破既有行为",**不能**证明计划提高了修复率。这条主张目前未证明,
  要证明必须真实模型批(人工授权后按 `docs/work-notes/swe-ablation-evidence-2026-10-07.md` 的
  预登记判据跑);
- −:消融臂(`single_shot`)不加计划段,因此将来任何两臂对照都必须先把 `plan_stage`
  登记进消融变量,否则对照会多出一个未登记的差异(本仓库已为此作废过一次付费实验)。
