# ADR 0010:候选工件 —— 恢复按候选重应用,绝不沿用旧结论

日期:2026-10-09 | 状态:已采纳 | 素材:PROGRESS.md S03、review F2(P0)、ADR-0006/0009

## 背景

ADR-0006 的恢复接线解决了"从哪儿续跑",但留了一个 P0 洞(外部审查 F2 实证):
恢复把 propose/apply/verify/rollback/finish 之后的工作区**一律先复位到基线**,
再执行检查点的 `next` 节点。next=finish 时,补丁刚被复位清掉,
finish 却按检查点里的旧 `verify_*` 布尔判 `resolved`——磁盘 diff 为空、
报告宣称修复成功。成功结论跨过了恢复边界,违反 ADR-0009 §4
("恢复只恢复输入、候选和进度,不恢复成功结论")。

## 候选方案

1. **把 finish 移出复位集合**:最小补丁,但恢复到 verify 时同样缺补丁,
   且"补丁从哪来"仍无答案——只是把洞从 finish 挪到 verify(被否)。
2. **恢复时不复位**:与块补丁锚点校验直接冲突,半截补丁会让续跑静默错位(被否)。
3. **候选工件**(采纳):在 PROPOSE→APPLY 交接点把实际 diff 冻结为带身份清单的
   工件;apply/verify/finish 的恢复一律"校验候选→reset→重应用→清旧结论→从 APPLY
   完整重验"。

## 结论

- **冻结点**:apply 节点入口(分支合流同路径)。`candidates/<candidate_id>/diff.patch
  + manifest.json`,tmp+replace 原子写;candidate_id 由 diff 内容派生(同 diff 幂等);
  manifest 携带 task_spec_hash/source_snapshot_hash/baseline_commit/round/父候选/
  生成 call_ids;读侧校验补丁字节 sha256 与清单一致,半写/篡改不可信。
  state 只存 candidate_id/candidate_hash(可序列化、进 checkpoint)。
- **ResumeDecision**:`prepare_resume` 返回结构化四态——continue(localize/plan/
  propose/rollback)、revalidate(apply/verify/finish)、reject(候选缺失/篡改/
  契约不符/源变/基线不符/无余额/无 deadline/无剩余步数)、already_terminal(END:
  只核对既有 report,不重跑不收费)。runner 按态分流,**恢复失败绝不默认冷启动**
  (冷启动=整份额度重发)。
- **revalidate 的动作序**:只读校验(候选 sha→受理契约→源指纹→基线→余额)
  → 决定入轨迹 → 复位前干跑落点校验 → reset+按既有 patcher 通路重应用
  (平台目录的候选**不跳门禁**,apply 节点照常全量执行)→ update_state 清旧
  verify/gate 布尔、as_node="propose" → invoke(None) 从 APPLY 完整重验。
  verify 每次真实重跑刷新 verification_attempt_id,成功绑定当前候选+当前尝试。
- **rollback 不提前复位**(对本卡前的行为修正):回滚节点要先保全 preserved_diff
  再自己复位;旧实现恢复时先复位会把末轮取证毁成空 diff。
- **服务恢复判定**纳入合法 checkpoint+candidate 边界:受理契约(task_spec.json)
  在场,且有候选工件或可用循环快照,才重新入队;旧任务缺身份证据判死不自动放行。
- 重验消耗剩余资源与剩余图步数,不增加 max_rounds(spec S03 边界)。

## 后果(含反方)

- +:F2 关闭——恢复到 apply/verify/finish 都有补丁正本,结论必须重新挣得;
  磁盘 diff、candidate_hash、fresh verification_attempt_id 与最终报告同源;
  next=finish 的旧格式检查点(无候选)如实 NEEDS_REVIEW,不伪成功。
- −:恢复路径更贵(重应用+门禁+双测试集+双跑复核全部真重跑);
  这是"证据属于当前尝试"的必要成本。
- −(反方,如实):S03 之前崩溃的任务没有候选工件,永远无法自动恢复到
  finish/verify 边界——宁缺毋滥,不做"从 report 反推候选"的猜测。
- −:拒绝恢复(而非冷启动)使僵尸任务收敛 NEEDS_REVIEW 的比例上升;
  这是诚实成本,换来的是额度不被恢复路径悄悄翻倍。
