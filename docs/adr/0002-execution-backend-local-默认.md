# ADR 0002:执行后端默认值 —— local 默认,Docker 可选

日期:2026-09-25 | 状态:已采纳 | 素材:interview-audit-2026-09-24.md 2-Q5;
docs/docker-isolation-notes.md 五项实验(2026-09-16 实测)

## 背景

被测代码在本机执行(local)还是容器内执行(docker)是判定可信度的核心选型。
审计 2-Q5 承认"为何不首选 Docker 无专门论证记录"。

## 候选

1. **Docker 默认**:判定面强隔离,但把可用性押在 Docker Desktop 守护进程上;
2. **local 默认 + docker 可选**(采纳)。

## 结论

`execution_backend: str = "local"`。理由:本项目是单机工具(threat-model §4,
不做多租户);工作区已是源仓库副本(snapshot.py),"改坏源仓库"风险在 gitops 层
已被隔离;判定完整性靠门禁(七项)+ verify 双跑复核(E3)这类结构防线,
而非容器边界;CI 与离线评测不能依赖守护进程状态(本轮 SPEC 红线亦明示
"不需要 Docker")。

Docker 后端的隔离边界有实测:五项实验(联网阻断/宿主文件不可见/挂载外不可达/
内存限额/正常跑 pytest)全部 PASS;剩余风险(内核共享、显式挂载可写、
资源旁路、时钟侧信道)如实记录在 docker-isolation-notes.md。

## Docker 默认化的前置条件(触发时重评)

镜像构建/分发流程化;Windows 下守护进程可用性验收(compose 冒烟已实测
停机窗口受理竞态);runs 目录"容器内路径=宿主视角路径"的 bind 挂载约束;
CPU/内存配额参数化;E3 之后成功路径 pytest 拉起 4→6 次,镜像需预热评估。

## 后果(含反方)

- +:零外部依赖开箱即跑;评测/CI 确定性不受虚拟化层干扰;
- −(反方):local 无 CPU/内存配额,失控测试仅受超时杀树约束,恶意代码可拖垮
  宿主;对"不可信代码"场景容器才是终态——本 ADR 的结论仅对"自建题 +
  单机研究"的当前定位成立,定位变化时必须重评。
