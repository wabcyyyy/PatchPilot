# ADR 0016: 工业试点生产契约与架构边界

- 状态：已接受 (Accepted)
- 日期：2026-10-15
- 关联卡：P00 (计划：[PatchPilot 工业使用改进计划](../work-notes/industrialization-plan-2026-10-15.md))

## 背景

PatchPilot 初始定位为单机个人开发工具，API 与执行器同进程，默认单用户回环绑定，缺少持久作业队列、独立执行 worker、严格主体身份与资源级权限隔离。
在进入企业内网受控生产试点阶段（单团队、单控制实例、单执行 worker）前，必须固化系统架构边界、权威数据源、安全信任模型与工作负载基准，消除潜在越权、资源耗尽及数据泄漏风险。

## 架构决定与契约

### 1. 部署形态与信任边界

- **双运行模式**：
  - `development`：保留现有单机轻量开发体验，支持回环绑定、可选 token、local/docker 后端；
  - `production`：强制实施严格准入。API 与 Worker 物理/进程分离。API 容器**严禁挂载 Docker socket**，无权直接执行用户代码或拉取镜像；Worker 在专用隔离机器/虚拟机上运行，仅由 Worker 守护 Docker daemon。
- **数据流向与出口管控**：
  - 用户请求 → API 网关 (认证/鉴权/准入/配额预扣) → SQLite 持久作业队列；
  - Worker 认领作业 (持有分布式租约/fencing token) → 隔离容器执行测试 → 原始工件持久化 → 提交状态；
  - 模型出口实施统一敏感凭据脱敏，公开接口与原始工件访问实施严格的基于主体的资源级访问控制 (RBAC)。

### 2. 核心实体的权威源 (Authoritative Sources)

| 实体 | 权威源 | 保证与约束 |
|---|---|---|
| 主体与凭据 (Principals & Credentials) | SQLite DB `principals`, `credentials` | 凭据单向不可逆哈希存储，支持受控吊销与轮换，不可自提权 |
| 任务与规格 (Tasks & TaskSpec) | SQLite DB `tasks` | 任务受理时冻结 TaskSpec，全生命周期不可篡改 |
| 作业与租约 (Jobs & Leases) | SQLite DB `jobs` | 事务化入队与领取，递增 fencing token，租约心跳续期，防双写 |
| 执行 Worker (Workers) | Worker 心跳与租约表 | 单实例互斥保护，失主任务经确认超时后可受控回收 |
| 工件与证据 (Artifacts & Evidence) | 任务工件目录 + DB 记录 | 原始测试输出与 JUnit 证据受保留策略与法律留置保护 |
| 预算与配额 (Budget & Quota) | 任务账本 + 组织配额表 | 预留 (reserve)、结算 (settle)、释放 (release) 三阶段核算 |

### 3. 不变量与禁区约定

1. `app/graph/acceptance.py` 继续作为 `resolved` 状态判定的唯一实现，不得为通过测试而修改测试期望或门禁规则；
2. 新增的审批状态 (`review_status`)、独立 CI 状态 (`independent_ci_status`) 为交付流阶段，不冒充图引擎内部终态；
3. 任务取消或超时未能在 5 秒内确认容器退出时，必须记录为 `execution_unknown`，保留配额与现场，严禁覆盖或复用工作区；
4. 配置与策略在任务受理时集中由 `Settings` 读取并冻结，运行期不可由模型或代码自举覆盖。

### 4. 负载基准与工程参数

正式冻结一份工业试点工作负载基准（见 [工作负载清单](../workload-manifest.md)）：
单 worker，执行并发 2，排队容量 20，并发受理 2，取消确认时限 5s，平稳演练时长 30m，API p95 ≤ 500ms，RPO ≤ 60s，RTO ≤ 120s。
