## 1. 真实模型实跑批(含 hard 题)——P3-1(审计 §2.6/§3 P3-1)

- **为什么必须人工**:真实 API 花费(钱包在用户手里,threat-model §5)。
- **前置依赖**:P3-3 守卫已合(commit 见整改报告)——`llm_model=""` 的复活链已堵死,
  report.json 不可能再落空 model_name;`.env` 凭据齐(用户文件,AI 未动);
  `PATCHPILOT_LLM_ENABLED=true`。
- **操作**:`python -m app.evals.run_single --bug BUG-0xx --model openai --out runs/real-<日期>`
  逐题跑,至少覆盖 1 道 hard 族(BUG-029..035)。
- **验收判据**:≥1 批 report.json 的 `model_name` 非空、`provenance` 完整(git_commit/
  config_snapshot 十键齐全);docs 报告的「真实模型成绩」声明仅在 provider=openai
  批成立(report.py 已自动把关)。
- **引用**:审计 §2.6(R1-Q2-2/R2-Q5)、§4 步骤 2。

## 2. --blind 盲跑对照批——P3-15 前半(审计 §2.8/§3 P3-15)

- **为什么必须人工**:与真实模型批同源的花费问题(E6 开关已就绪,0 次产出)。
- **前置依赖**:E6 `--blind` 已落(tests/test_driver.py 三用例钉死);建议与第 1 项同批产出。
- **操作**:`python -m app.evals.driver --bugs all --model openai --out runs/blind-<日期> --blind`

- **验收判据**:batch_manifest.json `blind=true`;同配置正常批与盲跑批各 ≥1 次,
  localize 贡献差值可计算;报告展示层出现「盲跑对照批次」标记。
- **引用**:审计 §2.8(R1-Q2-8)、§4 步骤 3。

## 3. graph+E3 补证实验——P3-5 后半(审计 §2.2 R3-Q7/§3 P3-5)

- **为什么列为人工**:fake 回放**零花费**,但用户明确归入勿代跑批次(与夜间 SPEC 先例一致)。
- **前置依赖**:P3-16 已合——`python -m app.evals.run_single --engine graph` 链路可用,
  driver 假 graph 入口已收口;`verify_double_run=True`(默认)。
- **操作**:用 fake 回放重跑若干题:`python -m app.evals.run_single --bug BUG-001
  --model fake --engine graph --out runs/e3-graph-<日期>`,检查三件套。
- **验收判据**:①run_dir/checkpoints.sqlite 物证存在;②trajectory 中 verify_double_run
  相关事件数 > 0(此前全 runs 树为零);③mismatch 值落盘。**证明力边界如实声明**:
  证明机制连通,不证明检出力——FakeLLM 确定性回放下 mismatch 恒 0 是构造使然。
- **引用**:审计 §2.2(R2-Q7/R3-Q7)、§4 步骤 5。

## 4. 干净树重跑基线批 + provenance 脏树指纹——P3-2(审计 §2.5 R1-Q2-1/§3 P3-2)

- **为什么必须人工**:重跑批次产生新证据(真实或 fake 均可,但脏树指纹属溯源语义
  小改,建议一并评审)。
- **前置依赖**:工作树干净(`git status` 无未提交变更);建议随批落地审计给出的
  provenance 增强:worktree_dirty + dirty_fingerprint 字段、manifest 落盘前
  `git ls-tree` 反查输入存在性(每批 1 次 subprocess)。
- **验收判据**:manifest 的 `git_commit` 在 `git ls-tree <commit> -- bugs/` 下存在
  所跑全部题目目录;fake36 式「锚点上不存在所跑题目」的坏锚不再可能;夜报/报告
  不再引用坏锚当证据。
- **引用**:审计 §2.5(R1-Q2-1)、§4 步骤 4。
