# PatchPilot 生产试点工作负载基准清单 (Workload Manifest)

版本：`workload-manifest-2026-10-15`。
关联卡：P00 / P19。状态：已冻结（作为准入与验收基线，不得跑完后迁就结果改写）。

## 1. 目标环境与拓扑

- 控制节点 (Control Plane / API)：
  - 进程/容器独立运行，**不挂载 Docker socket**，无容器启动权限；
  - 监听内网地址，必须启用主体身份认证与根路径白名单；
  - 部署形态：单控制实例。
- 执行节点 (Worker / Execution Plane)：
  - 专用机器或独立虚拟机，与控制节点及生产业务机物理/网络隔离；
  - 具备本地 Docker daemon，负责拉取并执行受信任 digest 的沙箱容器；
  - 容器以非 root (uid 1000) 运行，默认 `--network=none`，禁止提权；
  - 部署形态：单 worker 实例，通过数据库租约 (Lease) 与心跳串行认领作业。
- 存储与权威源：
  - 共享/挂载本地快速磁盘的 SQLite 数据库（WAL 模式），严格禁止跨网络文件系统（NFS/CIFS）直接挂载 SQLite；
  - 工件存储目录按任务隔离存放，受权限门禁控制。

## 2. 建议工程档位 (Baseline Parameters)

| 参数项 | 基准值 | 含义与硬约束 |
|---|---|---|
| 执行并发 (Execution Concurrency) | 2 | 单 worker 内部同时执行 pytest 容器的最大数量 |
| 排队上限 (Queue Depth Limit) | 20 | 待处理作业队列最大容量，超额返回 HTTP 429/503 |
| 并发受理上限 (Admission Concurrency) | 2 | API 层同时进行源码校验、冻结快照与准入扣额的最大并发数 |
| 单任务最大耗时 (Task Timeout) | 600s | 单个修复任务自认领至终态的全局超时硬上限 |
| 容器单次 pytest 超时 | 120s | 单次 pytest 执行的最大允许时长 |
| 取消退出确认时限 (Cancel Deadline) | 5s | 发出取消信号后，本地子进程或容器必须在 5 秒内确认已退出 |
| 持续负载演练时长 (Soak Duration) | 30m | 自动化故障与饱和负载演练的最短平稳运行周期 |
| 单任务单文件体积上限 | 10 MB | 源码冻结时拒绝的单个文件上限 |
| 单任务总源码体积上限 | 100 MB | 源码冻结时拒绝的任务源码总字节上限 |
| 单任务总文件数上限 | 5000 | 源码冻结时拒绝的任务包含文件总数上限 |

## 3. 服务等级与指标阈值 (SLO / Performance Thresholds)

- **API 延迟 (p95)**：
  - 任务状态查询 (`GET /api/tasks/{id}`) p95 ≤ 100ms；
  - 准入受理 (`POST /api/tasks`) 在有效缓存下 p95 ≤ 500ms（不计远端 Git clone 耗时）；
  - 取消响应 (`POST /api/tasks/{id}/cancel`) p95 ≤ 200ms。
- **故障恢复时效 (RPO / RTO)**：
  - **RPO (恢复点目标)**：≤ 60s（通过 SQLite WAL 刷盘与检查点机制保障）；
  - **RTO (恢复时间目标)**：≤ 120s（单 worker 崩溃或重启后，失主任务检测与安全收敛的最大时限）。
- **取消与清理保证**：
  - 任务取消、超时或 worker 异常时，关联执行单元（子进程或容器）在 5 秒内确认终止并回收；
  - 若在 5 秒内无法确认退出，状态必须记为 `execution_unknown`，保留配额锁定与现场，严禁提前复用工作区。
- **资源稳定性**：
  - 在 30 分钟持续负载演练中，控制面与 worker 内存 RSS 曲线进入平台期，无线性内存泄漏；
  - 日志与临时工件盘使用受到有界 tail 与配额保护，不发生磁盘无界增长。
