# 01 · 项目介绍

## 一句话

PatchPilot 面向 Python/pytest 仓库做测试失败诊断与补丁验证，平台独立执行测试并计算验收结论。

## 30 秒

“你提交仓库和缺陷描述，Agent 检索、提出补丁，平台在独立工作区验证原失败集与回归集。
resolved 要求补丁非空、双集全通过、门禁通过、预算内且未取消。它是可运行原型，
离线回放验证控制链；历史真实 SWE 实验有限，不宣称生产可用或官方成绩。”

## 90 秒

“LangGraph 负责阶段拓扑和检查点，每个模型阶段内部复用手写工具循环。
工具 schema 与执行能力来自同一阶段集合；AST/符号/字面搜索辅助定位，原始证据可分页取回，
平台观测进入任务记忆，模型只能写引用假设。块补丁经门禁和 Git/语法复检后，
平台重新跑具体测试，使用完整 JUnit 身份而非只看返回码。
最终共享 acceptance 不采信 finish 声明；graph 还绑定冻结候选，恢复时重应用并重验。
默认 local 不是沙箱，容器后端与单进程服务也有部署边界。
FakeLLM 回放含答案；真实模型与消融有历史记录、样本偏差和负结果，不能作为当前版本泛化收益。”

## 3 分钟补充

受理 TaskSpec 完整 hash 幂等、冻结 custom 输入副本、预检后双写契约，提交线程池。
Docker 预检不在宿主导入目标 conftest，只查 daemon；真实收集由容器 baseline 确认。
执行按受理配置建模型、账本与 runtime；未知消耗继续占预算，恢复不重授。
issue-only 清单由模型提议、平台基线复核、trusted_user 批准，不让模型自定成功标准。
失败回滚保全证据再复位、至多消耗一次轮次；任务终态与 stage 分开，迟到事件不能复活取消任务。
plain 是单轮替代驱动，共享工具循环与验收，功能不等同 graph。

## 证据与边界

详细链路见 [事实基座](00-project-audit.md)，实验见 [评测口径](05-evaluation.md)。
